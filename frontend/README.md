# Mu Metro React frontend

React + TypeScript + Vite, styled from https://numetro.co.za/. All movies, cinema locations, screening times, seat availability, accounts and bookings come from the Mu Metro API. There is no hardcoded catalogue fallback when the API is unavailable.

## Run the whole project

Requires Node.js 24 LTS. From the repository root:

```sh
npm ci
npm ci --prefix frontend
npm run setup
npm run db:seed:reference
npm run dev:full
```

Open http://localhost:5173. The API runs at http://127.0.0.1:3000. The existing `npm run dev` still starts only the backend; `npm run dev --prefix frontend` starts only the frontend.

The optional reference seed adds 12 film entries and seven days of fictional showtimes at the two demonstration cinemas. It preserves existing movies, accounts, seats, reservations and dates. Repeat it to append a fresh week as the schedule ages. `npm run db:seed` retains the original three-film fictional catalogue instead. Reference entries have illustrative metadata, including placeholder runtimes/release dates for unreleased films; they are not a live feed.

If port 5173 is already used, set `FRONTEND_PORT=5174` in the root ignored `.env` before running `dev:full`. A backend on another port can be selected with `API_PROXY_TARGET=http://127.0.0.1:3001`. The frontend uses relative `/api/v1` requests through the Vite proxy. For a separately hosted API, set `VITE_API_BASE_URL` in `frontend/.env` and configure that exact frontend origin in the backend's `CORS_ORIGINS`. Never put secrets in `VITE_` variables.

## Connected features

- Movie catalogue, search, now booking/coming soon and cinema/experience filters.
- Movie details, South African date filters, screening prices and showtimes.
- Registration, sign-in, profile validation, expiring sessions and server-side logout.
- Live seat maps refreshed every 20 seconds; atomic reservations for up to ten seats.
- Pending bookings, reservation countdown, cancellation, demo confirmation and booking history.
- Stable idempotency keys and a network retry for reservation/payment writes.
- Empty, unavailable and error states, keyboard-accessible dialogs, responsive navigation.

Passwords are never saved. The short-lived bearer token is kept in the current browser tab's session storage. Session expiry asks the visitor to sign in again. The server is authoritative for seat availability, status and totals.

Checkout uses the existing explicit `DEMO_PAYMENTS=true` configuration generated by `npm run setup`. It does not collect card details, charge money, or issue real tickets. When demo payments are disabled, the frontend cannot confirm a payment. Official partner, legal and social links are labelled external destinations; partner discounts and real Nu Metro inventory are not integrated.

## Production

```sh
npm run build:full
npm start
```

Fastify serves the compiled frontend and API on the same origin at http://127.0.0.1:3000. Hash-based navigation allows direct movie links without rewriting API failures to HTML. Docker builds and serves both parts using the existing compose configuration. The Docker build was not run in this development session.

Alternatively serve `frontend/dist/` from a web server and forward `/api` to the API. `npm run preview --prefix frontend` previews only the static build; use the Fastify production server to test the connected production deployment.
